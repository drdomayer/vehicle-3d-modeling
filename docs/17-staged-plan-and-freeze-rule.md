# 17 — Етапите и FREEZE правилото

Приет 2026-09-14. Заменя подхода „панел по панел до готов панел“, който води до разминавания
между панелите.

## Петте етапа

**1. Големи обеми.** Върху донорските hardpoints само масите: нос, предни калници, врата и канал,
задно рамо, заден deck, опашка. Без фарове, решетки и детайли. Целта е профилът вече да се чете
като рендера.

**2. По зони, не по панели.**
Група A — предница: целият преден обем първо, после фаровете се вкопават в него, после отворът.
Така фарът не може да излезе правилен сам по себе си, но залепен върху грешен калник.
Група B — страна: калник → празнина → канал → blade → рамо. Най-важната част от проекта.
Група C — задница: рамо → buttress → deck → капак → маска → дифузьор. **Обемът на покрива първи.**

**3. Детайли.** Чак когато големите повърхности са заключени. Тук вече се говори на милиметри:
„този ръб 3 mm навътре“. Това е refinement, не концептуално моделиране.

**4. Производствена версия.** Всеки панел става външна кожа + дебелина + вътрешна повърхност +
фланец + монтажни точки + клирънс + фуги.

**5. Производство.** Split, проверка срещу скана, клирънси, отваряния, файлове.

## Контролни точки

| | Какво се гледа | Какво НЕ се гледа |
|---|---|---|
| CHECKPOINT 01 | профил: дължина, височина, връзка с колелата, покрив, нос, задно рамо, раменна линия | фарове, дифузьор |
| CHECKPOINT 02 | предно 3/4: ширина, обем на калника, капак, фарове, централен отвор, негативно пространство | |
| CHECKPOINT 03 | задно 3/4: рамо, buttress, deck, капак, светлини, дифузьор | |
| CHECKPOINT 04 | всички изгледи: една и съща кола ли е отвсякъде | |

Ако CHECKPOINT 04 падне, връщаме се към повърхностната геометрия. **Не се добавят още детайли.**

## FREEZE правилото — машинария, не обещание

Одобрена зона се замразява. Оттам нататък строежът **отказва да се изпълни**, ако нещо, което
дефинира зоната, се промени, и казва точно какво се е променило.

Това не е документ, а код: `01_CAD/scripts/freeze.py`, състояние в
`01_CAD/scripts/data/freeze_state.json`, проверката се вика в началото на `build()` в
`statev_skeleton.py`.

```bash
python3 01_CAD/scripts/freeze.py                       # състояние
python3 01_CAD/scripts/freeze.py FRONT --freeze        # FRONT DESIGN APPROVED
python3 01_CAD/scripts/freeze.py FRONT --unfreeze "причина"
```

Зони: `FRONT`, `SIDE`, `REAR`, `ROOF`, `LIGHTS`. Кое принадлежи на коя е в `ZONES`.

Хешът покрива само данните, които определят геометрията — сеченията и размерите на елементите.
Промяна на бележка или коментар не го задейства. Промяна на размер го задейства.

Размразяването иска причина и тя се записва в историята на зоната.

**Защо съществува.** Предницата, страничният отвор и стоповете вече веднъж се разминаха, всеки по
веднъж. Правило, което живее само в документ, не спира това.

Проверено на 2026-09-14: замразена зона, преместен елемент с 5 mm, строежът отказа и назова зоната
и двата хеша. След връщане на промяната мина чисто.

## Как се говори за работа

Не „направи предния калник“, а:

```
Build the FRONT DESIGN VOLUME as one coherent surface system.
Do not finalize panel seams yet.
```

после

```
Freeze the front volume. Now introduce the headlight and functional intake
while preserving the existing surface character.
```

Това пречи на вече одобрени части да се преначертават.
